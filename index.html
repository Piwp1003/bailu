💬 副 API（选填，跑评论区 / 日程 / 小功能 / 游戏这些量大的活）

留空的话所有功能都走主 API，照常能用。填了之后按下面那张表分工：你会逐字读的（私聊、群聊、故事、日记信件）留在主 API，你多半只是扫一眼的（评论区、路人、日程、状态、小功能里的一句话、游戏决策）交给副 API——所以副 API 适合挂便宜快的小模型。
📋 主 API / 副 API 分别负责哪些功能（点开看全表）

走「向量 API」（第三套，在「记忆」那一页单独填）
向量记忆Embedding 拉取模型 / 生成向量。填了用它，没填退回主 API，永远不会去用副 API。
控制AI回复的随机性/重复度，全部留空＝不发送该参数，使用服务商默认值。不确定的话不用改。
✂️ 回复老是写到一半就断掉？就是这一项。
max_tokens 是"这次最多允许生成多少 token"，撞到上限模型就会被硬切断，句子停在半截。留空＝不发送这个参数、用服务商自己的默认值（多数是 4096）， 觉得不够就填大一点，比如 8192。注意它只是上限，模型写多少就按多少计费，调大不会让平时的回复变贵。
用推理模型（deepseek-reasoner / QwQ / 带 thinking 的中转）尤其要注意：有些中转会把思考过程直接塞进正文里， 那段思考同样占 max_tokens——于是经常出现"思考写完了，正文一个字还没写就到上限了"。这种情况要么把上限调大， 要么换成不带 thinking 的模型。
被截断时右下角会弹一条提醒，告诉你是撞上限了，而不是让你对着半句话猜。
两种模式二选一，切换随时可以改回来：想控制回复长度/省token用"可控字数模式"；觉得被总字数卡得不够自然、更喜欢旧版本那种聊天感觉的可以切回"经典模式"——这是照搬旧版本的原始设定，条数固定随机1~4条、每条想写多长写多长，不设总字数上限。
💡"聊天回复总字数"是AI一次回复（可能拆成好几条消息分开发）加起来的总预算，不是每条单独的上限；具体分几条发、每条写多少字，由AI自己在"最少~最多条数"范围内决定。（这一段仅在"可控字数模式"下生效；切到"经典模式"后这两个条数输入框会隐藏、也不再生效，侧滑重新生成也会跟着走经典模式、不再被总字数砍短。目前只剩"拍一拍反应"这类一句话的即时反应仍然沿用总字数，那本来就是短回应，不影响正常聊天的手感）
你写信寄出去之后、或者日记被角色偷看之后，Ta不会立刻有反应，而是隔一段随机时间（在下面这个范围内随机抽一个数）才会回信/留批注——也可以直接点"⚡立即回复"跳过等待。
这是最影响 API 花费的一项。以前是"角色库里每一个角色都来评论一次"——有多少角色就发多少次请求， 每次都带着那个角色的完整人设+世界书。27 个角色时实测一条推文要 9 万 token。
限制之后会按相关度挑人：被 @ 到的 → 关系网里有连线的 → 最近聊过天的 → 关注的 → 其余随机， 评论区照样热闹，但请求次数固定住了。填 0 = 不限（恢复以前的行为）。
